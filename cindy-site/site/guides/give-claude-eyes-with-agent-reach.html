What it actually is

Agent Reach is a capability layer, not another scraper. It does not read anything itself. For each platform it keeps an ordered list of backends (a first choice plus fallbacks), installs the working one, and runs a health check so your agent knows what it can currently reach. Your agent then calls those upstream tools directly.

That distinction matters for a boring but important reason: access paths break constantly. The repo's own example is Bilibili 412-blocking yt-dlp in June 2026, which moved that platform onto a different backend with no action from users. You are installing the router, not betting on one scraper staying alive.

Free, genuinely Every backend is an open-source tool with a free API path. The only line item is an optional proxy (about $1/month) and only if your network blocks these sites. Local machines need nothing.
Local credentials Where a platform needs a login, the cookie stays on your machine. Nothing is uploaded, and the whole codebase is open if you want to read it.
Any agent Anything that can run shell commands works: Claude Code, the Claude desktop app's terminal, Cursor, Windsurf. It is a CLI, not a Claude-only plugin.
Self-diagnosing One command, agent-reach doctor, prints which platforms are live, which need a step from you, and what that step is.

What works instantly, and what does not

This is the part the viral reels skip. "Install it once and just ask" is true for some platforms and not others, and knowing which is which saves you an hour of confusion.

  1. ✅ Zero config, works the second it installs. Any web page (via Jina Reader, turning a URL into clean Markdown), YouTube subtitles and video search (yt-dlp), public GitHub repos and code search (the gh CLI), any RSS or Atom feed, and V2EX. Web search is wired up during install through Exa, free and with no key of your own.
  2. 🍪 One cookie export, then it works. Twitter/X needs an auth token exported from your browser before search, timelines and full tweet reading unlock. Your agent walks you through it if you ask it to.
  3. 🔐 Needs a logged-in browser session. Reddit, Instagram and Facebook ride your existing desktop Chrome session through OpenCLI. Reddit specifically has no zero-config path any more, because the anonymous endpoints are blocked and the official API is gated. Desktop only.
  4. 🔗 Partial out of the box. LinkedIn reads public pages through Jina Reader immediately. Full profiles, company pages and job search need the LinkedIn MCP backend configured.
Read this before you connect accounts. Riding a logged-in session to read Reddit, Instagram or Facebook is a grey area under those platforms' terms of service, and doing it at volume is a good way to get an account limited. Use it for reading and research at human pace, keep it off your main account if that account is your business, and never point it at anything you would not be comfortable explaining.

The setup, start to finish

You do not run an installer yourself. You hand your agent the install document and it does the work, which is the actual novelty here.

  1. 👩‍💻 Check the two prerequisites. You need Python 3.10 or newer (python3 --version in a terminal tells you) and an agent that is allowed to run shell commands. Claude Code, Cursor and Windsurf all qualify out of the box.
  2. 📋 Paste the install line to your agent. Open Claude Code in any folder and paste the block below. It fetches the install document and follows it: installs the Python package, checks your machine, and reports what is ready.
  3. 🛡️ Approve system changes deliberately. By default the install only checks your machine and lists what is missing. It writes nothing system-level until you say yes. If your agent asks to re-run with --system, read what it wants to install before agreeing.
  4. 🔎 Run the health check. Ask your agent to run agent-reach doctor. You get a list like "6/9 channels available" with a tick next to what works and a fix prescription next to what does not. This is your source of truth, not a blog post.
  5. ➕ Unlock only what you need. Tell your agent "help me set up Twitter" or "help me set up Reddit" in plain language. It knows what each one requires and walks you through it. Skip the platforms you do not use.
  6. 📦 Optional: install it as a skill. If your agent supports skills, run npx skills add Panniantong/Agent-Reach@agent-reach. The skill teaches your agent which command to reach for, so you never memorise CLI syntax.
📋 paste this to install 
Install Agent Reach: https://raw.githubusercontent.com/Panniantong/agent-reach/main/docs/install.md

4 research prompts worth the install

Installing it is not the point. This is the point. Each of these is a real research job that Claude could not do before, and each one is written to make it show you evidence rather than a confident summary.

🧠 mine Reddit for real pain points 
Use Agent Reach to search Reddit for what people actually complain about regarding [your topic, product category or niche], across the subreddits where that audience really posts rather than the obvious big one.

Pull at least 30 posts or comments from the last six months, and quote the complaints verbatim in their own words rather than paraphrasing them into marketing language, because the exact phrasing is the thing I want. Group them into recurring themes, rank the themes by how often they come up and how emotional the language is, and note which ones already have a good answer in the thread versus which ones nobody solves. For every theme, give me the single best verbatim quote and a link to the thread it came from so I can verify it myself.
👩‍💻 study a competitor's best video properly 
Use Agent Reach to pull the full transcript of this YouTube video: [URL]. Then pull the transcript of the two or three other videos on that channel with the highest view counts.

Break each one down structurally rather than summarising it: what the first fifteen seconds do to earn attention, how the body is sequenced, where the pace changes, what specific claims or numbers are used as proof, and how it closes. Then tell me what is repeatable across all of them versus what only worked because of that specific topic. Finish with the three structural moves I could apply to my own content this week, and be blunt about which parts of their approach would not suit me.
🔎 scan the reaction before you post your take 
Use Agent Reach to search Twitter/X for reactions to [topic, product launch or announcement] over the last two weeks, and read the replies to the highest-engagement posts, not only the posts themselves.

Map the argument: what are the two or three genuinely distinct positions people hold, who is making each one, and what evidence does each side actually cite. Separate the takes that are informed from the ones that are just repeating a headline, and flag any factual claim that keeps getting repeated without a source. Then tell me which angle is already saturated and which one is underserved, and quote the specific posts you drew that from with links.
🌱 build a standing research feed 
Use Agent Reach to set me up a weekly research loop on [your niche]. Find the five or six most useful RSS or Atom feeds and the two or three most active GitHub repositories in this space, and confirm each one actually returns content before you include it.

Once you have them, read the last week of each and write me one brief: what genuinely changed, what is just noise, and what it means specifically for someone doing [your work]. Keep the same structure every week so I can compare briefs at a glance, and where you are inferring significance rather than reporting something stated outright, label it so I can tell the difference. Save the feed list somewhere reusable so the next run does not start from scratch.

3 things before you rely on it

It routes, it does not guarantee. Platforms break access paths on their own schedule. If something worked last week and does not today, run agent-reach doctor first, then update with the same one-line pattern (swap install.md for update.md in the URL). Most breakages are a re-route, not a dead end.
Never point it at anything sensitive. You are giving an agent shell access and, for some platforms, your live browser session. Install it in a folder you do not mind it touching, read what it proposes before approving system changes, and treat any tool that asks for a login the way you would treat a browser extension asking for the same thing.
💡 The realistic value. The killer use is not "scrape everything." It is that audience research stops being a tab-juggling chore. Asking one question and getting back thirty real quotes with links is a genuinely different working day, and that alone justifies the twenty-minute setup.
