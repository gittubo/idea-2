why this order

Map, build, control, then habits

Most people start with the hour-long course, get twenty minutes in, and quit. The order below exists so each video answers the question the last one left you with.

  1. 🗺 First the map. Ten minutes that name every part of the tool, so the words in the longer videos already mean something.
  2. 🛠 Then build something. Nineteen minutes that end with a real thing deployed to a real URL. Momentum matters more than completeness at this stage.
  3. 🎛 Then the controls. The settings hour. This is what stops Claude Code wandering off, burning context and rewriting files you did not ask it to touch.
  4. 🔁 Then the habits. The team that builds Claude Code showing how they actually run it day to day, which is a different thing entirely from knowing the features.
The honest total is 1 hour 55 minutes. That is four evenings, not one sitting. Doing one a night and using the tool in between is the version that actually sticks.
before video one

Get it installed in five minutes

Do this first so you can follow along instead of watching. Everything here is from Anthropic's official setup page.

  1. 💻 Mac, Linux or WSL. Open Terminal and run curl -fsSL https://claude.ai/install.sh | bash. On a Mac, Homebrew works too: brew install --cask claude-code.
  2. 🪟 Windows. In PowerShell, run irm https://claude.ai/install.ps1 | iex. Or use WinGet: winget install Anthropic.ClaudeCode.
  3. 🖱 Not a terminal person? There is a Claude Code desktop app with a graphical interface, so you never touch a command line. The setup page links the Mac, Windows and Linux downloads at the top.
  4. ✅ Check it worked. Run claude --version. You should see a version number. If something looks off, claude doctor prints a read-only diagnostic of your install and settings without starting a session.
  5. 🚀 Start it. Open a terminal inside the folder you want to work in and type claude. It logs you in through your browser the first time.

paste this in

The starter CLAUDE.md

Three of the four videos land on the same point: the file that tells Claude Code about your project is what makes it good. Most people write three lines and wonder why it keeps guessing. Create a file called CLAUDE.md in your project folder and paste this in, then answer the bracketed parts.

📄 write my CLAUDE.md for me 
Look through this project, then write me a CLAUDE.md file for it and save it in the root of the folder.

Work out what the project actually is before you write anything: what it does, what it is built with, how it runs locally, where the important files live, and any patterns that repeat across the codebase. Where you cannot tell from the files, ask me rather than guessing.

The file should contain: a two-line description of the project, the exact commands to install, run and test it, a short map of the folder structure with one line per important directory, the conventions you should follow when writing code here, and a short list of things never to touch without asking me first.

Keep it under a page. Write it as instructions to you, not as documentation for a human, and leave out anything you could work out by reading a single file.
Then keep it alive. Every time you correct Claude Code on something it should have known, add that correction to the file as one line. After a fortnight it stops making the same mistakes, and that is the whole trick.
night one

Your first real session

Watching without building is how this stays theoretical. After video one, open a new empty folder, run claude, and paste this.

🚀 build my first thing 
I have never used you before, so go slowly and explain what you are doing as you go.

I want to build a small single-page web app that [describe the thing you actually want, in one sentence, for example: tracks which of my subscriptions renew this month and totals them up].

Start in plan mode. Tell me what you intend to build, which files you will create, and what it will look like when it works, then wait for me to say go before you write anything.

Once I approve the plan, build it, run it locally, and tell me the exact command I need to type to see it in my browser. If something breaks, show me the error and explain what it means in plain words before you fix it.
the four nights

A schedule that actually finishes

  1. Night one, 10 minutes. Video one, then install it and run the first-session prompt above. End the night with something running locally.
  2. Night two, 20 minutes. Video two, following along. End the night with a project on GitHub and a live URL.
  3. Night three, 45 minutes. Video three from 7:26 to about 45:00. Set your permissions properly and write your CLAUDE.md while it is fresh.
  4. Night four, 25 minutes. Video four, then pick one loop or routine from it and set it up on your own project.
Skip nothing on night one and two. The settings hour only makes sense once you have felt the problems it solves. Watching it first is how people conclude Claude Code is complicated.
