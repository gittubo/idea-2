Set it up step by step

  1. Confirm Node.js 18.18 or newer and either a ChatGPT subscription with Codex access or an OpenAI API key.
  2. Add OpenAI's plugin marketplace, install codex@openai-codex, reload plugins, and run /codex:setup.
  3. Run a read-only review first. Use /codex:review --background, then /codex:status and /codex:result.
  4. Create the route skill below. Keep one system as planner and reviewer, and give Codex a bounded task with acceptance tests.
  5. Stop the loop after a defined number of revisions or when a test fails for an external reason. Escalate the blocker instead of burning usage.

Create the /route skill

📋 copy this
Create a reusable skill called route. When I invoke /route with a task, first interview me only for missing requirements that would materially change the implementation. Then write a short plan, acceptance criteria, protected files, and a maximum of two implementation-review cycles. Delegate the bounded implementation to Codex through the official plugin. Require Codex to report changed files, tests run, failures, and unresolved risks. Review its diff against the acceptance criteria and existing repository instructions. If the work fails review, send one precise correction. Never widen scope, expose secrets, run destructive commands, or claim success while tests are failing. Return the final diff summary and evidence.
check the work

Quality gate before you trust it

1 /codex:setup reports that Codex is ready.
2 The first delegated job is read-only and its result can be retrieved.
3 The route skill defines scope, acceptance criteria, protected files, and a loop limit.
4 Usage is tracked under the connected Codex account; the guide makes no promise of unlimited or free usage.
5 Claude reviews the actual diff and test output, not just the executor's summary.
6 Save the source links, as-of date, and final evidence beside the output so another person can reproduce the check.
