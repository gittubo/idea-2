Make your Claude usage last longer (the planner and executor setup)

💡 What you need. Claude Code installed and any paid Claude plan. If you're not in the terminal yet, there's a manual version of the same idea at the bottom that works in normal chat windows.
build it first

The executor subagent

A subagent is a separate worker Claude can hand jobs to, and it can run on a different model from your main session. That model choice is the entire trick. Anthropic's docs list it as a first-class reason to use subagents: "control costs by routing tasks to faster, cheaper models like Haiku" (Claude Code subagents docs).

  1. 📁 Open your agents folder. In your project, that's .claude/agents/. Create the folder if it isn't there yet. For an agent you want everywhere, use ~/.claude/agents/ instead.
  2. 📝 Create executor.md. Make a new file called executor.md in that folder and paste the block below into it. You can also ask Claude Code to create the file for you, then check the model: line yourself.
  3. ⚡ Check the model line. The model: field accepts sonnet, opus, haiku, fable, a full model ID, or inherit. Left out, it defaults to inherit, which means it quietly runs on your expensive model and saves you nothing. Set it to haiku.
  4. 🧠 Leave your main session on the top model. Opus 4.8 or Fable 5 stays where you are. It plans, delegates, reviews. It never does the grind.

Here's the whole file. The model: line is the part doing the work:

⚡ .claude/agents/executor.md 
---
name: executor
description: Executes a plan the main model already wrote. Use for the repetitive, mechanical work, never for big judgment calls.
model: haiku
---

You carry out a plan that has already been decided. Do not redesign it.
- Follow the steps exactly and in order.
- Do the repetitive work: edits, formatting, boilerplate, repeated passes.
- If something is genuinely ambiguous, stop and ask instead of guessing.
- When you finish, list what you changed so it can be reviewed.
📌 Sanity check it worked. Ask Claude in that session to run one small repetitive job and tell you which agent handled it. Then re-open executor.md and confirm the model: haiku line is still sitting inside the --- frontmatter block at the top. If that line is missing or reads inherit, the executor is quietly running on your expensive model and saving you nothing.
why it works

Pay your smartest model to think, not to type

Running Opus 4.8 or Fable 5 on file renames is like paying a senior strategist to do data entry. They'll do it beautifully and it's a waste of the thing you're paying for. Cheaper models cost a small fraction per token of the top tier (Anthropic's pricing), and the grind is where nearly all your tokens go, so moving the grind is where the savings live.

The manager (top model)

Opus 4.8 or Fable 5. Writes the plan, defines what "done" means, then reviews the finished work before it reaches you. It works twice per job, at the start and at the end, and that's where its power actually pays off.

The executor (Haiku)

Fast and far cheaper per token, so it grinds through everything in between: the edits, the boilerplate, the repeated passes. Same volume of work, a fraction of the budget.

run the job

Plan, execute, review

  1. 🧠 Plan (top model). Your main session writes the plan and sets the standard: what the finished work has to look like, and what counts as passing.
  2. ⚡ Execute (executor subagent). The work gets handed to Haiku, which follows the plan step by step. This is the token-hungry part, so this is the part you make cheap.
  3. 🧠 Review (top model). The manager checks the result against its own standard, fixes what's off, and only then hands it to you. Top-model quality without top-model prices on every keystroke.

Paste this into your main session to run all three in one go:

🧠 plan, delegate, review 
Here's the job: [describe the task, e.g. "reformat these 20 blog posts and add a summary to each"].

Work as the manager, not the worker:
1. First, write a clear plan and define what "done" looks like as a checklist I can see.
2. Then hand the actual execution to my executor subagent to do the repetitive work.
3. When it's finished, review its output against your own checklist, fix what's off, and only then show me the result.

Do not do the grunt work yourself. Your job is to plan and to check.
leave it running

Make it hands-off with /loop and /goal

Two native Claude Code commands take you from "run it each time" to "it keeps going without me". Both are built in, so there's nothing to install (Claude Code commands docs).

♻️ /loop Runs a prompt repeatedly while the session stays open. Give it an interval, like /loop 30m re-run the executor on the next batch and report what changed, or leave the interval off and Claude paces itself between passes.
🎯 /goal Sets a condition, and Claude keeps working across turns until it's met or judged impossible. For example /goal every post is reformatted and each one has a summary under 40 words. Use /goal clear to remove it afterwards.

They stack, and stacking them is the point. /goal decides what passing means, so your top model has something specific to review against instead of eyeballing it, and /loop keeps the passes coming while you're doing something else.

📌 Give the goal numbers. "Make it good" is not a condition Claude can judge, so the goal never resolves and the loop never ends. Write it as something a stranger could mark pass or fail: a count, a limit, a checklist.
the honest bit

What this does and doesn't do

What it does: stretches your top-model budget a long way, because the model that burns the most now only plans and reviews. And because something senior inspects the work before you see it, the output comes back cleaner than if you'd done it all in one expensive session.
What it doesn't do: give you infinite usage. Nothing does. If you're pinned at your ceiling every day, a higher plan is the real answer. This is about spending the budget you have on the right model for each job.
💡 No terminal yet? Run the same shape by hand: ask your top model for a plan and a checklist, open a separate chat on a cheaper model to execute it, then bring the result back to the top model to review against the checklist. The subagent version automates that hand-off for you.
