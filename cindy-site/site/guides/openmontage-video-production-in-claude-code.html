honest first

What it is actually best at

Point it at a blank prompt and ask for a video about a topic, and you will get something competent and generic. That is the trap. The value is in the repurposing pipelines, the ones that start from footage that already exists, because that is where the machine does the tedious work and your taste still decides the output.

So the framing I would give you: this is a rough-cut assistant, not a creative director. Feed it long footage you already made, let it do the passes that make your eyes glaze over, and keep the final cut on your desk.

Clip factory Takes one long source and returns a batch of ranked short-form clips. This is the pipeline that pays for the whole setup.
Podcast repurpose Turns podcast highlights into video. Good for the audiogram and highlight-reel work nobody wants to do manually.
Talking head Footage-led speaker videos, for presentations, vlogs and interviews. This is the one to test with your own camera footage.
Localisation and dub Subtitles, dubbing and translation for a video you already have, which is the cheapest reach you will ever buy.
⚠️ Licence check before you use it commercially. OpenMontage is released under the GNU AGPLv3, not a permissive licence. Making videos for your own channel or your clients is fine. Building it into a product you host for other people is where the AGPL's conditions bite, so read the licence properly before you do that.
before you install

Four things you need

Python 3.10 or later Free, from python.org. Most Macs already have a version, and the installer will tell you.
Node.js 18 or higher Free, from nodejs.org. This is what runs the rendering engine.
FFmpeg The free video toolkit that does the encoding and mixing. brew install ffmpeg on a Mac, sudo apt install ffmpeg on Linux, or grab it from ffmpeg.org.
An AI coding assistant Claude Code is what I use, and the repo also works with other AI coding assistants like Cursor and Codex. Install steps are in the Claude Code docs.
setup

Install it in three commands

  1. 📥 Clone the repo. Open your terminal, go to wherever you keep projects, and run git clone https://github.com/calesthio/OpenMontage.git. This downloads the whole thing to your machine.
  2. 📂 Move into the folder. Run cd OpenMontage. Everything from here happens inside that folder, which is also the folder you will open in Claude Code.
  3. ⚙️ Run the setup. Run make setup. This builds a Python environment, installs the dependencies, installs the Remotion rendering engine, installs the free Piper text-to-speech voice, and creates your .env file. It takes a few minutes and prints a lot of text, which is normal.
  4. 🪟 On Windows, or if make is missing. The repo's readme has a full one-line fallback for macOS, Linux and Windows PowerShell that does exactly the same steps by hand. If npm install fails on Windows with an ERR_INVALID_ARG_TYPE error, the documented fix is to run npx --yes npm install instead.
  5. 💻 Open the folder in Claude Code. In your terminal, inside the OpenMontage folder, start Claude Code. It reads the project's own instruction files and becomes the thing that runs the pipelines. There is no separate app to launch.
🧠 There is no API key step, and that is deliberate. The setup gives you a working free path out of the box. Keys are optional extras you can add later, and every one of them costs money, so skip them until you have a reason.
first message

Orient it before you ask for anything

The repo ships with its own instruction files, and the difference between a good first session and a confusing one is whether your assistant read them. Make that the first thing you ask for.

🧭 orient yourself in this repo 
Read AGENT_GUIDE.md and PROJECT_CONTEXT.md in this project before you do anything else, then tell me what I'm working with in plain English, assuming I'm a creator and not an engineer.

Specifically: list the pipelines available to me, say which of them work right now with no API keys configured, and name which free tools are doing the work in that no-key path. Then tell me the single pipeline you'd recommend I try first if my goal is [cutting my long videos into short clips / editing my own talking-head footage / making an explainer from scratch], and why that one.

Do not start a production yet. I want the lay of the land first.
the real use case

Turn one long video into a batch of clips

This is the pipeline to test first, because it is the one where the output is judged against footage you already trust. Have a long video ready: a webinar, a podcast episode, a long-form YouTube video, anything over ten minutes.

🎬 run the clip factory on my long video 
Use the clip factory pipeline on this source video: [file path or link]. My goal is vertical short-form clips for Instagram and TikTok, each between 30 and 60 seconds.

Before you cut anything, transcribe it and give me a ranked shortlist of the ten strongest moments, with a timestamp, a one-line reason each is strong, and a suggested hook line for each. I want moments that are a complete thought on their own, not a sentence that only makes sense if you heard the previous five minutes. Wait for me to pick which ones to build.

Then, for the ones I choose, cut them, add word-level captions, and render them vertically. Show me the ranking logic you used so I can tell you what you got wrong about my audience.
🌱 The shortlist is the whole point. Reading ten timestamped moments takes you two minutes and it is where your taste enters the process. If you let it cut straight to finished clips, you have outsourced the one judgement call that was actually yours.
make it yours

Train it on your editing style

The system's knowledge lives in readable markdown files, over 700 of them, in a skills/ folder. That is the customisation surface. You are not editing code, you are writing down your editing preferences in plain English so the agent applies them every run instead of you re-explaining them.

✍️ write my house style into a skill file 
I want you to capture my editing style as a reusable style file in this project, so every future production follows it without me repeating myself.

Here's how I edit: captions are [style, position, font feel], cuts are [tight with no dead air / breathing room between beats], my hook is always in the first [X] seconds and it is [a question / a claim / a result], I never use [stock-looking B-roll / trending audio / zoom transitions], and my videos end on [your sign-off]. My audience is [who they are] and the tone is [warm and practical / fast and punchy].

Read how the existing style and skill files in this repo are structured, write mine in the same format and the correct location, and then tell me exactly which pipelines will pick it up and how I'd change it later.
what it costs

The free path is real, the paid path is optional

This is the part I want to be exact about, because "free AI video" usually means "animate some still images and hope". Here, with zero API keys configured, the setup gives you a genuinely working stack.

  • Narration: Piper TTS, a free offline text-to-speech engine that runs on your own machine.
  • Real footage: a searchable corpus built from Archive.org, NASA and Wikimedia Commons, so the documentary montage pipeline cuts actual motion footage rather than panning across photos.
  • Extra stock: Pexels, Unsplash and Pixabay, whose developer keys are free to get.
  • Rendering: Remotion for React-based compositions, plus an HTML and GSAP renderer for motion-graphics-heavy briefs.
  • Post and captions: FFmpeg for encoding, mixing and subtitle burn-in, with auto-generated word-level captions built in.

The paid layer is a long list of optional generation providers you add as API keys in the .env file, and every one of them bills you directly. None of them are free tiers dressed up, they are pay-as-you-go accounts you open yourself. The repo publishes real costs for its own showcase videos, including a 60 second animated short it produced for $1.33 and a 50 second vertical film for about $4, which is a useful reality check on what generated footage actually costs. The full provider list with pricing is in the repo's providers document.

⚠️ Add a spend cap before you add a key. The system has budget controls, cost estimation before execution and per-action approval thresholds built in. Turn them on in your first paid session rather than the session after the surprise.
when it goes sideways

The four things that trip people up

"ffmpeg: command not found" FFmpeg is not installed or not on your path. Install it, close the terminal completely, reopen it, and run the setup again.
The render looks like a slideshow You asked for a topic with no footage source. Ask for the documentary montage path and say "use real footage only" explicitly, which is the documented way to get motion footage.
It invents a workflow Your assistant skipped the instruction files. Tell it to read AGENT_GUIDE.md and the pipeline manifest and to follow the pipeline rather than improvising.
The output is generic Expected, on a blank-prompt topic video with no style file. Write your style file, and start from footage or a reference video rather than a bare topic.
worth trying

Start from a video you already like

One feature genuinely worth knowing about: it can take a reference video, a YouTube video, a Short, a Reel or a local clip, analyse its transcript, pacing, scenes and style, and come back with differentiated concepts, an honest tool path and a cost estimate before it produces anything. For anyone who finds a blank prompt paralysing, that is a much better on-ramp than inventing the perfect brief from nothing. The repo's prompt gallery has tested prompts with expected costs if you want more starting points.
