How to make Claude run your computer for you

the shape of it

What "Claude runs your computer" actually means

There is no single button called autopilot. What exists is four separate capabilities that stack, and the reason the phrase sounds dramatic is that most people have only ever used the chat box. Chat is Claude answering. These four are Claude doing: opening tabs, clicking things, writing files, checking its own work, and starting again tomorrow without you.

You do not need all four. Pick the one that matches the task you keep redoing, get it working once, then add the next layer when you feel the friction.

🌐 The browser layer Claude in Chrome, an extension that drives your real browser in your real logged-in tabs while you watch.
🔁 The build loop Claude Code writes something, opens it in the browser, reads the console errors, and fixes what it broke.
⏰ The schedule layer Routines and scheduled tasks that start a session on their own, hourly, nightly or on an event.
🔌 The connector layer MCP connectors that give Claude direct access to Notion, Gmail, Drive, Slack and hundreds more.
⚠️ The plan gates, all in one place, so nothing surprises you. Claude in Chrome and the Claude Code Chrome integration need a direct paid Anthropic plan (Pro, Max, Team or Enterprise) and a Chromium browser on desktop, with no mobile version (Chrome integration docs). Cloud routines are a research preview available on Pro, Max, Team and Enterprise with Claude Code on the web enabled (routines docs). Desktop scheduled tasks need the Claude Code desktop app, which requires a paid subscription. Connectors work on claude.ai on every plan, free included. Full pricing: claude.com/pricing.
layer one

Claude in Chrome: it clicks, you watch

This is the one that makes people sit up. The extension puts Claude in a side panel next to whatever you have open, and it drives your browser: your tabs, your logins, your session. That matters, because it means Claude can work inside things you are already signed into rather than hitting a login wall on every site.

  1. 🧩 Install the extension. Search "Claude in Chrome" in the Chrome Web Store and add it. It works in Chrome and Edge, and it also connects in other Chromium browsers like Brave, Arc, Vivaldi and Opera. There is no version for Safari or for phones.
  2. 🔐 Sign in on a paid plan. Sign in to the extension with the same account you use on claude.ai. This is a beta feature on paid plans, so a free account will not see it. Anthropic's overview of what it does and how they thought about the safety side is here: Claude for Chrome.
  3. 📍 Open the side panel on the site you want. Navigate to the page first, then open the panel. Claude reads the page you are on, so you do not need to paste screenshots or describe what is on screen.
  4. ✅ Grant permission per site. The first time Claude wants to act on a site, it asks. You can allow that one action or allow the site for the session. This per-site gate is the whole safety model, so read the dialog rather than clicking through it on reflex.
  5. 👀 Stay in the room for the first few runs. Watch what it clicks. Agentic browsing is a multi-minute thing, not a two-second thing, and the first time you run a new task is when you find out your instructions were vaguer than you thought.
  6. 🛑 Know where stop is. You can interrupt at any point. Claude also pauses on its own at logins and CAPTCHAs and asks you to handle those manually, and it will not push through a payment step without checking with you.

Getting-started details and the current feature list live in Anthropic's help centre article: Get started with Claude in Chrome.

A first browser task worth running

Start with something read-only and boring. The point of run one is to see how it moves, not to hand it your bank account.

🌐 the browser research run 
I have [site or tool] open. Work through it in my browser and pull together the information I keep collecting by hand, without changing, sending or deleting anything.

Specifically: go through [the section, list or filter, for example "my orders from the last three months" or "the first three pages of listings"], open each item, and record [the fields you actually need, for example the name, the date, the price, the status and the link]. Keep going until you have covered every item in that view, and tell me how many you found so I know nothing was skipped.

Give me the result as a table I can paste into a spreadsheet, sorted by [the field that matters to you]. If anything is ambiguous, or a page will not load, or you hit a login, stop and tell me rather than guessing or filling in a plausible-looking value. Before you start, list the actions you are about to take so I can approve them.
🌱 A tiny detail that saves you: tell it what NOT to touch. "Do not send, submit, delete, purchase or reply to anything" in your first line costs you eight words and removes almost every way a browser run can embarrass you.
layer two

The build loop: Claude tests its own work

This is the layer people underrate, and it is the one the whole reel is named after. On its own, a coding assistant writes something plausible and hands it to you to find the bugs. Connect it to a browser and the shape changes: it builds, opens the page, reads the actual console errors and the actual DOM, and fixes what is broken before you have seen it. That closed loop is the difference between a draft and something that works.

  1. 💻 Install Claude Code. It runs in your terminal, in VS Code and JetBrains, in a desktop app, and on the web. Pick whichever is least scary. Install instructions: Claude Code overview.
  2. 🧩 Use the same Chrome extension. Claude Code drives the browser through the Claude in Chrome extension you installed in layer one, version 1.0.36 or higher. One install covers both layers.
  3. ▶️ Start the session with the browser turned on. Launch with claude --chrome. The first time, you get a one-time dialog explaining how site permissions work. You can also set Chrome on by default so you stop typing the flag.
  4. 🔍 Check the connection. Type /chrome at any point. It is connected when the panel shows "Status: Enabled" and "Extension: Installed". If you have several browsers open, this is also where you choose which one Claude drives.
  5. 🔑 Sign in properly. Chrome integration needs a normal /login sign-in on a direct Anthropic plan. If you authenticate with an API key or a long-lived token, Claude Code keeps the browser integration switched off, which is the usual reason it silently does not work.
  6. 🧪 Ask for the loop, not the code. The phrasing matters. "Build it" gets you code. "Build it, open it, test it, and fix what you find" gets you the loop. The prompt below does that explicitly.
🔁 build it, then break it yourself 
Build [what you want, for example "a single page that takes a CSV of my expenses and shows a monthly total and a category breakdown"], then verify it yourself in the browser before you tell me it is done.

Work in this order and do not skip a stage. Write the code. Start it locally and open it in Chrome. Then actually use it the way a first-time visitor would: click every button, submit the form with valid input, submit it again with empty and obviously wrong input, resize the window to phone width, and read the browser console for errors and warnings after each action.

For every problem you find, tell me what broke, what caused it, and fix it, then re-run the whole check from the top. Keep looping until a full pass produces no console errors and no broken interaction. When you are done, give me a short list of what you tested, what you fixed, and anything you could not test without me, for example something that needs a real login or a real payment.
💡 The same loop works on things that already exist. Point it at a page you own and ask it to walk the flow, read the console, and report what a real user would hit. It is the cheapest QA pass you will ever run.
🧠 Bonus layer, honestly labelled: Claude Code can also drive your actual desktop, not only the browser. Computer use is a research preview on macOS that needs a Pro or Max plan and an interactive session, and it is not available on Team or Enterprise. It lets Claude open apps, click, type and see your screen, which is how it tests native apps it has written. Details: computer use in the CLI.
layer three

Scheduled agents: work that starts without you

A session you have to start is still a task on your list. Scheduling is what turns a workflow into something that has already happened by the time you sit down. There are three ways to do it and they are genuinely different, so pick on the constraint rather than the name.

  • Routines run in Anthropic's cloud, so they keep running with your laptop shut. They can fire on a recurring schedule, on an API call, or on GitHub events like a new pull request, and one routine can carry several triggers. Minimum interval is one hour, and they run autonomously with no permission prompts. Research preview, on Pro, Max, Team and Enterprise: routines docs.
  • Desktop scheduled tasks run on your own machine through the Claude Code desktop app, so they can touch your local files and your local tools. They fire only while the app is open and the computer is awake, and the minimum interval is one minute: desktop scheduled tasks.
  • /loop repeats a prompt inside a session you already have open, which is the right tool for polling something for the next twenty minutes rather than for a nightly job: running prompts on a schedule.
  1. 📝 Write the job as a paragraph first. Before you touch any scheduling UI, get the instruction working in a normal session. A routine is a saved prompt plus repositories plus connectors, so if the prompt is vague you have automated a vague result.
  2. ➕ Create it. Routines are created from the web at claude.ai/code/routines, from the Routines page in the desktop app, or by typing /schedule in the CLI. The desktop Routines page is also where you choose between a local task and a cloud routine.
  3. 🕘 Set the cadence, honestly. Nightly beats hourly for almost everything. Ask what time you actually want to read the output, then schedule it to finish an hour before that.
  4. 🔒 Scope the permissions. Cloud routines run without asking you anything, so keep the first ones to reading, summarising and drafting. Anything that sends, publishes or deletes should stay in a session where you are watching.
  5. 🧾 Make it report to you. End every scheduled prompt with an instruction to write its output somewhere you will actually look: a file, a doc, an email draft. An agent that ran perfectly into a void is the same as one that did not run.
  6. 🔁 Read the first three runs properly. Then adjust the prompt. Automation that nobody has checked is the kind that quietly does the wrong thing for a month.
⏰ the Monday morning brief routine 
Every Monday at 6am, put together my week-ahead brief and save it as a dated markdown file in [folder], then leave the whole thing in the run output so I can read it on my phone.

Pull from the sources I have connected: my calendar for the next seven days, anything in [tool, for example Notion or a task list] that is due or overdue, and unanswered items from [inbox or channel] that are older than two days. Do not act on any of it. Do not send, reply, publish, schedule or delete anything, and if something looks urgent, flag it in the brief instead of handling it.

Structure the brief as: the three things that genuinely matter this week and why, anything with a hard deadline and the date, what slipped from last week, and the single task I should do first on Monday morning with one sentence of reasoning. Keep it under 400 words, plain language, no motivational filler. If a source is empty or fails to load, say so explicitly rather than leaving a gap that looks like good news.
⚠️ Routines are a research preview, which means the behaviour, the limits and the interface can change. Treat anything you build here as something to re-check every few weeks, and do not put a business-critical process behind it until you have watched it run clean for a while.
layer four

Connectors: give Claude the tools you already pay for

A connector plugs Claude into a system directly, so it can read and act there instead of working from whatever you paste into the chat. They run on the Model Context Protocol, an open standard that any tool can implement, which is why the list keeps growing rather than being a fixed set of integrations (MCP).

  1. 🧭 Find the directory. In Claude, open Customize, then Connectors. That is the browse-and-add screen, and it works on every plan including free. Background reading: about connectors.
  2. ➕ Add the ones you use daily. Connect the tool, sign in through its normal login screen, and approve the access it asks for. Read that approval screen properly, because it is where you decide what Claude can reach.
  3. 🔧 Add anything missing as a custom connector. If a tool is not in the gallery but publishes a remote MCP server, choose add a custom connector and paste the URL: custom connectors.
  4. ⌨️ In Claude Code, use the CLI. Run claude mcp add to attach a server to a project, and /mcp to see status, authenticate or disable one. Start here: MCP quickstart.
  5. 🧹 Keep the list short. Every connected tool is more surface area and more for Claude to sift through. Four you use beats twenty you added once and forgot.
  6. 🔍 Check what each one can actually do. Some connectors are read-only, some can write. Knowing which is which before you schedule anything is the difference between a summary and a surprise.
🗂️ Your notes or docs tool Notion, Drive or similar. This is the one that makes Claude answer from your actual work instead of general knowledge.
📅 Calendar and email Turns "what is my week like" and "draft the reply" into one message. Keep email on drafting rather than sending.
💬 Your team chat Slack or equivalent, so Claude can catch up on a thread you were tagged in and summarise the decision.
🎨 Whatever you make things in A design or publishing tool. Being able to hand off the finished thing is what stops the workflow one step short.
🔌 the connected weekly catch-up 
Using the tools I have connected, catch me up on [project or client] and tell me what needs a decision from me. Read only, no sending or editing anything.

Go through: every message in [channel or thread] since [date], the notes or pages in [notes tool] tagged to this project, anything on the calendar that relates to it, and any documents that changed in the last two weeks. Then tell me what actually happened, in order, with dates.

Split your answer into: decisions that were already made and by whom, open questions with the person who is waiting on me, anything that has slipped past a date, and the two or three things I should handle first. Quote the source line for anything important so I can click through and check it myself. If two sources disagree, show me both instead of picking one, and if you could not access something, name it.
put it together

Pick one boring task and hand over the whole loop

Four layers is interesting. One task running end to end is useful. The upgrade is going from "Claude helped me with that" to "that happens now", and the way in is a task that repeats weekly, has a clear finished state, and does not need your judgement in the middle.

  1. 🎯 Choose the task by boredom, not importance. The weekly numbers pull, the standing report, the folder of receipts, the same three sites you check every Monday. If it makes you sigh, it qualifies.
  2. 🖐️ Do it once with Claude watching. Run it manually in a session and narrate what you are doing and why you make each call. This is where the real instructions come from, because you know things about this task that you have never written down.
  3. 📄 Write it down as a repeatable instruction. Turn that session into a paragraph precise enough that a competent stranger could follow it. If you want it permanent, save it as a skill so it triggers by name every time. There is a full walkthrough in my Claude skills guide.
  4. ⏰ Schedule it and let it run supervised. Put it on a routine or a desktop task, then read the output for three runs before you trust it. Adjust the prompt each time rather than accepting output you would not have sent yourself.
🧠 design my loop 
Here is a task I do every week and want to hand over: [describe it properly, including what you open, what you copy, what you decide, and what finished looks like]. Help me turn it into something that runs without me.

First, ask me the questions you need to pin down the parts I have left vague, especially anything where I make a judgement call, and wait for my answers before designing anything. Then tell me which parts of this are genuinely safe to automate and which parts should keep a human approval step, and be honest if the whole thing should stay manual.

Then design it across the four capabilities: what needs your browser, what needs to be built or written, what should run on a schedule and how often, and which connected tools you would need. Write me the exact prompt I would save as the scheduled job, including the instruction to report its output somewhere I will see it. Finish with what could go wrong on a bad run and what I should check on the first three runs.
the honest bit

What this does not do

Three things worth knowing before you build your week around it. Agentic runs are slow compared to the demos: a real browser task is minutes, not seconds, so this buys back attention rather than raw clock time. Permissions are the whole safety story, which means anything running unattended should be scoped to reading, summarising and drafting, with sending and deleting kept in sessions where you are present. And Claude cannot tell that the source data was wrong, so an automation that runs perfectly on bad inputs produces confident, wrong output on a schedule. The review step is the part you keep.

The reason the loop matters more than any single feature is that checking its own work is what makes handing something over reasonable at all. Build, test, fix, repeat, then report back to you. That is the whole thing, and it scales from one page you are debugging to one task you never think about again.
