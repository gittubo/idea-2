Two ways to do this

🐟 Route 1: the Fish Audio dashboard (start here)
You create an agent in your browser, give it a job and a voice, talk to it, and publish it. No code, no API key, nothing to install. Every build below has a dashboard version of its first step, and this is how you find out in ten minutes whether the idea works for you.
👩‍💻 Route 2: a custom build with a coding assistant
You open a coding assistant (this guide uses GPT-6 Astra inside the ChatGPT desktop app), paste a build prompt, and it writes a small program that talks to Fish Audio's API with an API key you create. This is what you need the moment an agent has to book a calendar, write to a CRM, call leads on its own, or run inside a web page.
⚠️ Being signed in to Fish Audio in Chrome does not connect it to your coding assistant. The assistant only reaches Fish Audio through an API key you save in your project (route 2) or through the Fish Audio MCP server you add in the ChatGPT app (it generates speech, transcribes audio and makes images and video, but it cannot create agents, see below). Nothing is connected until you do one of those two things.
route 1, about ten minutes

Build and test an agent in the Fish Audio dashboard

  1. Open Agents. Go to fish.audio/app/agents in your Fish Audio account and click New agent. Give it a name and you land in the Builder. Agents is in public beta and open to every account, nothing to apply for, and every account starts with a one-time US$5 trial balance, about 60 minutes of conversation, and it pays for real usage of every kind: web sessions, phone calls and API calls. The Builder's own test calls are free and never draw on it.
  2. Give it a job. On the Configuration page, write the system prompt in plain English: who it is, who it talks to, what it may and may not say, what to do when it doesn't know. Keep it under about 1,500 words: Fish Audio recommends staying under 2,000 tokens, and anything past the 32,000-token hard cap is rejected outright. There's no save button; edits save automatically as a draft (watch for Saved bottom-left).
  3. Set the first message. Under First message choose Fixed message and type the greeting, for example "Hi, you've reached Cindy's Studio, I'm the AI assistant, how can I help?" Say it's an AI here; people should never have to guess.
  4. Pick the voice and language. In the voice panel click Choose a voice (More voices opens the library, My Voices holds your clones) and set the Speaking language. Picking a voice doesn't change the language, so set both. Speed and expressive mode live here too.
  5. Add what it needs to know. Open the Knowledge base tab and click New private file. Paste your hours, services, prices, address and policies. Only Markdown or plain text works (PDFs and Word files have to be converted first), up to 1 MB per file.
  6. Talk to it. Click Test call in the top bar, then Start call, and let the browser use your microphone. Ask it something from your file, then something that isn't in it. Test calls run your draft, are free, and stop after ten minutes (or your agent's own maximum call duration, whichever is shorter).
  7. Publish. When it behaves, click Publish. That freezes a version; real sessions, phone calls and the web widget only ever connect to a published version. Builder test calls always run your draft, so they never need a publish. Everything outside the Builder (the web widget, a phone call, your own page) fails with a 409 error until you publish, which is Fish Audio's way of saying "publish first".
🌱 Your route 1 finish line. In one test call the agent answers a question that is in your knowledge file correctly, says it can't help with one that isn't (instead of making something up), and takes your name and number to pass on. Get that, then publish. If you only ever need a browser agent that answers questions, you're done, and you never touched a key.
💡 A test call is a test call. It proves the brain and the voice, in your browser, with your microphone. It is not a phone line. For real calls the published agent needs a number: buy a US or Canada number from the workspace Phone numbers page ($1.20 a month; the docs describe this through the API, so the console may or may not offer a buy button on your account), or click Import number to connect a number you already own through your carrier's SIP trunk (the only way to use a non-US number). Bookings, CRM updates and anything outside the conversation need a webhook tool pointing at a small program you host, which is exactly what route 2 builds.
🧐 One note on access. Two separate Fish Audio doc pages now say Agents is in public beta, open to every account, no application needed, so you should see New agent the moment you open that page. My contact there was still talking about beta access in mid September, so in the unlikely event you get a waitlist button instead, apply and nudge support.
route 2, do this once

Set up the custom-build route

Only needed for builds that reach outside the conversation: calendars, CRMs, calling leads, or a web page of your own. The assistant does the coding; you do these seven things once.

  1. Pick a plan that matches the use. Free is for personal projects only: about seven minutes of generated speech a month, a 500-character limit per generation (Plus lifts that to 15,000, which matters the moment a script runs longer than a paragraph), and the plan page's FAQ limits it to non-commercial use. The feature table on that same page confusingly shows a commercial-use bullet on Free, so if you spot that, the FAQ is the restrictive one. Anything for a business, a client or an ad needs Plus or above (Plus is US$11 a month billed annually, US$132 a year, or US$15 month to month) on the Fish Audio plans page. Agents, phone calls and the API are billed separately from that subscription; keep reading.
  2. Clone your voice. In your Fish Audio account, clone your own voice from at least ten seconds of clean audio (one to two minutes sounds better) following the voice cloning docs. Copy the voice ID from the voice's page. Note that Voice Design (describing a voice in words) is for auditioning; it doesn't save a reusable ID. Library voices and clones do.
  3. Create an API key. Go to fish.audio/app/api-keys, click Create New Key, name it (for example "receptionist build") and set an expiry if you like. Copy it once; you won't see it again. One key covers both speech and Agents. Treat it like a password.
  4. Store the key where the code can read it. Make a folder for the project. Inside it create a file named .env containing one line, FISH_API_KEY=paste-your-key-here, and a file named .gitignore containing the line .env so the key never gets uploaded anywhere. The programs the assistant writes read the key from that file (in Python that's the dotenv library, in Node it's dotenv or the built-in env file support). Never paste the key into a chat, never put it in the web page's own code, and never share a screenshot of it.
  5. Know your three IDs. You'll be handling three different strings and they are not interchangeable. The API key proves it's your account (from the API keys page, goes in .env, is sent as Authorization: Bearer). A voice ID says which voice to speak with (from a voice's page in the library or My Voices). An agent ID names one specific agent (shown in the Builder's address bar once you create it). Prompts below ask for the voice ID; the assistant finds or creates the agent ID.
  6. Open GPT-6 Astra in Codex. In the ChatGPT desktop app, open the dropdown above the message box and choose Codex, then open your project folder. Choose Local under the message box: Codex's cloud mode strips secrets and blocks internet access by default, so the easy path is your own computer. Astra is not offered in Codex cloud at all, which makes Local the only route to it. Use the model and reasoning control beneath the message box. It lists presets rather than raw model names, so pick Astra Light, or open Advanced to choose the model yourself. Plus gets a limited number of Astra messages a day. If Astra isn't offered at all, that is your plan, the rollout, your sign-in method or your client, not an out-of-date app. (/model is the command-line way of switching, not the desktop app's.) Light reasoning is fine for these builds. Set permissions to Ask for approval and click Approve when it asks to reach Fish Audio or install something.
  7. Turn Plan mode on, and leave it on. Type /plan (or press Shift+Tab). Plan mode makes Astra ask its questions and show you a plan before it changes anything; you say yes, it builds. It is a toggle, not a per-build command, so typing it again before your next build switches it back off: check it is on rather than retyping it. Outside Plan mode, "ask me first" is only sometimes honoured. The setup prompt and all eight build prompts assume you're in Plan mode.
🧠 Paste this once: the setup prompt 
You are GPT-6 Astra, my setup assistant for a Fish Audio project. I have never coded, so explain anything technical in a few plain words, and never install or change anything without asking me first.

First, look at what I already have. List the files in this project folder. Check whether a .env file exists and which key names it holds (names only, never the values). Check that .gitignore exists and lists .env; if not, offer to create it. Check which MCP servers and connectors are connected in my ChatGPT (run /mcp if you can) and tell me whether the Fish Audio MCP at https://api.fish.audio/mcp is one of them. Ask me anything you cannot see.

Then check my Fish Audio access, one item at a time:
1. Is FISH_API_KEY in .env? If not, tell me to create one at https://fish.audio/app/api-keys/ (Create New Key) and add the line FISH_API_KEY=my-key to .env myself. Never ask me to paste the key into this chat.
2. Prove the key works without exposing it: load it from .env and make one harmless read-only request, such as listing my voices or my agents. Report only the HTTP status and what it means in plain words (works, wrong key, expired key, no access to Agents yet). Never print the key, the headers, or the full response.
3. Do I have a voice ID from a cloned voice or a library voice? If not, explain how to clone one from ten seconds of clean audio. Voice Design is for auditioning voices and does not save an ID.
4. Which plan am I on, and roughly how much API credit balance do I have? Remind me that Agents, phone calls and the API are billed from the prepaid API credit balance, not from the web subscription, and that every account starts with a one-time $5 trial for calls.
5. Which country am I in? Numbers bought through Fish Audio are US or Canada only and can call the US, Canada, Japan, the UK, Italy, Australia and Mexico. If I am elsewhere, note that I will need to import my own number.

Give me a short table: what is ready, what is missing, and what you suggest for each gap. Then fix the gaps with me one at a time, asking before you install anything (for example cloudflared for a temporary public address, or ffmpeg for video). Do not buy a phone number, spend credits or call anyone. Finish by telling me I am ready to start a build, or exactly what still blocks me.
🌱 Run it in Plan mode with your Fish Audio account open in another tab. The one request it makes is read-only and costs nothing. It ends with either "you're ready" or the exact list of what's missing.

MCP or API? Two doors, two wallets

Three different things wear the word "AI" in this guide, and it helps to keep them apart. The coding assistant (GPT-6 Astra in Codex) is the builder: it sits on your computer, writes the program and runs it, and only exists while you're chatting with it. The runtime model inside your Fish Audio agent is the voice on the line: once the build is done, Fish Audio's own model (Gemini 3.5 Flash Lite, GPT-5.6 Luna or Gemma 4 are the included ones, chosen in the Builder) answers callers with no ChatGPT involved. And the MCP server is a cable between the two.

🔌 The MCP server
A bridge you add once in the ChatGPT app (Settings, then MCP servers, then Add server: name it fish-audio, choose Streamable HTTP, paste https://api.fish.audio/mcp, Save, Restart, Authenticate; type /mcp to check). It lets the assistant browse the voice library, generate speech, transcribe audio, and make images and video, and it bills your web plan's package credits, the same pool the website uses. It cannot create agents, buy numbers or place calls. Builds 5 and 6 use it; the phone builds don't.
🔑 The developer API
What the key in your .env unlocks: everything, including Agents, phone numbers, outbound calls, transfers and post-call analysis. It bills a separate prepaid API credit balance that you top up in your account. Your web subscription doesn't cover it, and the $5 trial lives here. Builds 1 to 4, 7 and 8 use this.

Costs, recording and the rules you own

💡 What it actually costs (API credit balance). Everything here is in US dollars. Conversations are US$0.06 a minute with the basic models included. Phone calls add a carrier surcharge on top: US$0.01 a minute for most calls, but Australian mobiles add US$0.09, so an Australian mobile is about US$0.15 a minute all in rather than US$0.07. Japanese mobiles add US$0.22, UK and Italian mobiles US$0.03 to US$0.05. A bought number is US$1.20 a month, transfers add US$0.015 (cold) or US$0.025 (warm) a minute, and ringing that isn't answered is free. Full table on the agent pricing page. Bringing your own number removes the rental, the Fish surcharge and the transfer fees, but your carrier still bills you, and outbound calling and warm transfer only work on it if your carrier setup supports them.
🎙️ Decide about recording before you publish, don't inherit it. Recording is on by default in every new agent. Telling callers "this is an AI" is not the same as getting consent to record; many places need explicit consent or a spoken notice. So make a real decision: keep recording on and add the notice your jurisdiction needs, or turn it off in the agent's Settings and rely on the post-call summary. The prompts below default to off until you've checked.
📵 If your agent calls people (builds 2 and 3), you own the rules. Get consent before an AI calls someone, honour an opt-out ("stop calling me" must work), respect calling hours and any do-not-call list where you operate, and have the agent say it's an AI up front. Fish Audio's docs don't handle this for you. Outbound calling also has to be switched on for your workspace; if a call comes back with an outbound-disabled error, that's what it means, and the docs don't say how it's enabled, so ask their support.
🧱 Five things that break builds silently. Paste these into Astra if it gets stuck.
1. An agent has to be published. Editing the draft isn't enough. A 409 error saying there's no published version means this.
2. Webhooks can't point at your laptop. Fish Audio rejects localhost and private addresses, so any build with a webhook needs a public HTTPS address. For testing, a free Cloudflare quick tunnel works with no account.
3. Custom variables don't reach webhook tools. Only tool arguments and the built-in system variables do, so booking details must be declared as tool arguments.
4. The widget needs a served page and an exact origin (builds 7 and 8). Opening the HTML file by double-clicking it gives an origin of file://, which matches nothing, and the allowlist matches scheme, host and port exactly. Run the page on a local web server on a fixed port, and list both http://localhost:5173 and http://127.0.0.1:5173, because Fish Audio counts those as different origins. Otherwise the widget dies with a 403 and no explanation.
5. An answering machine now counts as answered (builds 2 and 3). Fish Audio removed answering-machine detection, so a call that rolls to voicemail still reports as answered and your agent will happily talk to the beep. Tell it to hang up if nobody answers its first question, and read the transcript before you trust a "booked" or "qualified" result.

Testing on your laptop is not running it for real

🧪 Fine for testing
A program running on your laptop with a temporary Cloudflare tunnel, keys in a local .env, and you watching the terminal. This is how every build below is meant to be tried. It stops the moment your laptop sleeps or the tunnel closes, and the tunnel address changes every time.
🏁 Needed to run it for real
A small always-on host for the program (any cheap cloud box or app host), the key stored as a secret on that host rather than a file, a fixed HTTPS address that only accepts requests from Fish Audio (check the signature or a shared secret), logs you can read, and an alert when calls fail. Ask Astra for exactly this once a build has passed its test; it's a separate step, not the default.

Prefer to build your own voice stack?

Hosted Agents is the whole point of this guide, but if you're a builder who wants full control there's an advanced alternative: speech recognition to turn the caller's words into text, a conversational model (any you like) to decide what to say, Fish Audio speech synthesis to say it in your voice, and a voice orchestration or telephony layer to hold the call together. It's four services, latency tuning and real engineering, not a one-key replacement for Agents. Ask Astra for a plan only if you already know why you'd want it.
