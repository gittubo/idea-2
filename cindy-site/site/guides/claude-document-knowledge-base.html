why this works

Folders store, knowledge bases answer

Folders are built for putting things away. That is a completely different job from getting an answer out. So you can have twelve immaculate folders and still spend twenty minutes opening PDFs one at a time looking for one number. A knowledge base flips the direction: instead of you remembering where the fact lives, you ask a question and the system goes and finds it.

Claude gives you both halves of that for free. A Project holds the documents and answers from them. An artifact turns the same material into a page you can search, click and share. You build the brain once, then the front door on top of it.

part one

Build the Project (the brain)

  1. 🧠 Open Projects. Go to claude.ai/projects or click Projects in the left sidebar of the Claude app, then click + New project in the top right. Projects work on every plan including Free, and Free accounts can hold up to five projects at a time (source).
  2. 📄 Name it after the question you will ask. Not "documents" and not "misc". Name it the way you would search for it later: "client contracts", "my content library", "unit 3 lecture notes". Future you is scanning a list of five project names, so make them do some work.
  3. 📥 Add your documents to project knowledge. Click the + inside the project and upload your files. Anything you add here is available to every chat inside that project, so you upload once instead of re-attaching the same PDF forever. Supported types include PDF, DOCX, XLSX, CSV, TXT, HTML, RTF, EPUB and JSON, and project files are capped at 30MB each (source).
  4. 🏷️ Rename files before you upload. This is the step people skip and it is the one that pays off most. "2026-Q2-supplier-contract-northside.pdf" beats "scan_0043.pdf" forever, because the file name is what Claude quotes back at you when it tells you where an answer came from.
  5. 💡 Write the project instructions. Every project has a custom instructions box. This is where you tell Claude what these documents are, who you are, and how you want answers shaped. Use the prompt below and paste the result in.
  6. 🌱 Add more than you think you need. When a project grows past what fits in one context window, Claude switches to retrieval automatically and searches your material instead of loading all of it, which lets a project hold roughly ten times more content. That is on every plan, Free included, and there is nothing to switch on (source).
paste this in

The project instructions

Paste this into the custom instructions box of your new project, filling in the two brackets. It is what makes answers come back sourced instead of vague.

🧠 project instructions 
These documents are [describe what they are, for example "every contract, invoice and supplier agreement for my business since 2024"]. I am [describe your role and what you use them for, for example "the owner, and I mostly need to find specific clauses, dates and amounts quickly"].

When I ask you something, answer only from these documents. Always name the exact file you took the answer from, and quote the relevant line or paragraph so I can verify it myself. If the answer sits across several documents, list each one separately rather than blending them into one summary.

If the documents do not contain the answer, say so plainly and tell me what kind of document would be needed to answer it. Never fill a gap with a general guess about how things usually work, because a plausible wrong answer is worse to me than no answer. Keep replies short and factual by default, and only go long when I ask you to explain something.
then ask

The question that proves it is working

Start a chat inside the project and run this. It is deliberately a hard ask, because you want to see the sourcing behaviour before you trust it with anything real.

🔎 interrogate my own files 
Search everything in this project's knowledge and answer this: [your real question, for example "which of these contracts auto-renew, and what is the notice period on each"].

For every part of the answer, name the file it came from and quote the exact sentence. Then tell me which documents you checked and found nothing relevant in, so I know the search actually covered the whole set and not just the first thing it matched.

Finish with anything that looks contradictory between documents, or any place where two files say different things about the same fact. Flag those separately at the bottom under a heading called "conflicts to check".
The "tell me what you checked and found nothing in" line is the trust builder. It turns a confident-sounding answer into one you can actually audit, and it exposes the case where your file never made it into the project at all.
part two

Build the front door (the artifact)

The Project is great for asking. It is not great for browsing, and it is not something you can hand to another person. That is what the artifact is for: a single interactive page, built from the same documents, with a search box at the top.

  1. 🧠 Stay inside the project. Open a new chat within the project so Claude still has all the documents in its knowledge. Building the page from outside the project means it has nothing to build from.
  2. 💡 Ask for the page. Paste the build prompt below. Claude will write it as an artifact, which appears in its own window beside the chat. Artifacts are available on Free, Pro, Max, Team and Enterprise plans (source).
  3. 👀 Test it like a stranger. Type a half-remembered word into the search box. If nothing sensible comes back, tell Claude exactly what you searched and what you expected, and it will fix the filtering. Two or three rounds of this is normal and it is where the page gets genuinely good.
  4. 📄 Keep it or share it. Use the download control in the lower right of the artifact window to save the file, or publish it to a link if you want someone else to browse it. Both are in the same panel.

The build prompt

👩‍💻 build the searchable page 
Using every document in this project's knowledge, build me a single self-contained interactive HTML page as an artifact. It should be a browsable index of everything in here, so I can find the right document without opening files one by one.

Give it a search box at the top that filters live as I type, matching on title, summary text and tags, with no page reload. Under that, put filter buttons for the categories you think fit this material, and show a count of how many items are currently visible. Then render one card per document containing the file name, a two or three sentence plain-English summary of what is actually in it, the key dates, names or numbers it contains, and three to five tags. Clicking a card should expand it to show a longer summary and the most important quoted lines from that document.

Read every document properly before you write the summaries, do not guess from the file names, and do not invent any detail that is not in the source. Sort the cards newest first where the documents have dates. Make it work on a phone as well as a laptop, keep the styling clean and readable with plenty of white space, and put everything in one file with no external dependencies so it still works if I save it and open it offline.
then upgrade it

Three refinements worth asking for

Run these one at a time in the same chat, checking the page after each.

🔎 add a fuzzy search 
Improve the search so it still finds the right card when I half-remember something. Make it case-insensitive, match partial words anywhere in the text rather than only from the start, and search the long summaries and quoted lines as well as the titles and tags.

If a search returns nothing, show a friendly empty state that lists the five closest matches instead of a blank screen. Keep everything else on the page exactly as it is.
🧠 add a "what changed" view 
Add a second view to the page, toggled by a button next to the search box, called "timeline". It should lay every document out in date order with the most recent at the top, each one showing its date, file name and one-line summary.

Where two documents cover the same subject at different dates, group them together and note in plain language what changed between them. Use only what is actually in the documents, and if a document has no date, put it in a clearly labelled "undated" group at the bottom.
🌱 add an open-questions panel 
Add a collapsible panel at the bottom of the page called "gaps and open questions". In it, list the things a reasonable person would expect this collection to contain but which are missing, and any place where two documents contradict each other.

For each item, say which documents led you to that conclusion. Be specific and conservative: only raise something if the documents genuinely support it, and do not pad the list to make it look thorough.

Four knowledge bases that earn their keep

Your content library Every script, caption and post you have written. Ask it what angles you have already covered before you write a new one.
Client and contract admin Contracts, invoices, scopes and briefs. Ask it what a client is actually owed and get the clause quoted back.
Study or course notes Lecture slides, readings and your own notes. Ask it exam-style questions and make it cite the week the answer came from.
House and life admin Insurance, warranties, leases, appliance manuals. The category everyone loses and nobody has indexed.
honest limits

Four things to know before you rely on it

A project is not synced to a folder on your computer. Nothing updates itself. When a document changes you upload the new version and delete the old one, otherwise Claude will happily answer from the outdated file. Build the top-up into a routine rather than trusting yourself to remember.
Free accounts are capped at five projects, so pick your five categories rather than making a project per week. Project files are 30MB each, and very large scanned PDFs are the usual thing that trips this.
Scanned documents that are really just photos of pages give weaker answers than text-based files, because there is less clean text to search. If a PDF was produced by a scanner, expect to check its answers more closely.
The artifact is a snapshot, not a live mirror. It reflects the documents as they were the day you generated it. Regenerating it takes one message, so treat it as something you refresh rather than something that maintains itself.
keep it alive

The ten minute monthly top-up

  1. 📥 Add what is new. Drop this month's documents into the project knowledge, renaming them properly on the way in.
  2. 🗑️ Remove what is superseded. Delete the old version of anything you replaced. One outdated contract in there is enough to make an answer wrong.
  3. 🔎 Ask it what shifted. Run the prompt below so you get a summary of what actually changed rather than assuming.
  4. 💡 Regenerate the page. Say "rebuild the index page with everything currently in the project knowledge" and you get a fresh front door in one message.
🌱 monthly review 
I have just added new documents to this project. Compare them against what was already in the knowledge and tell me what has changed.

List anything that supersedes an older document, anything that contradicts something already in here, and any new dates, amounts or obligations I should know about. Name the specific files on both sides of each comparison.

Then tell me which older files are now safe to delete because a newer version covers them, and which ones I should keep even though they look redundant, with a one-line reason for each.
