Cross-model project folder

Download the starter folder

Download: https://cindyzhu.com.au/guides/files/cross-model-project-starter.zip

Unzip it at the root of a new or existing project. Review every example before an AI uses it. Do not put credentials, private customer data, or unapproved claims into shared context.

The folder tree

├── AGENTS.md
├── CLAUDE.md

What each part does

PROJECT_MAP.md

The front door for a person or model:

  • what the project is
  • what matters now
  • current owner
  • definition of done
  • where each kind of truth lives

Keep it short. A map points somewhere; it does not contain the whole company.

Decisions

Record choices you do not want reopened every session:

  • what was chosen
  • owner and date
  • evidence and trade-offs
  • consequences
  • measurable condition for revisiting it

Do not hide an unresolved proposal inside the decision log as if it were approved.

Processes

Store repeatable instructions:

  • outcome
  • required inputs
  • exact steps
  • objective quality checks
  • human approval point
  • edge cases learned from real runs

Update the process when reality disagrees.

References

Stable rules, approved examples, definitions, source links, brand rules, and facts. Give every reference an owner and last-reviewed date.

Inputs and Outputs

  • Inputs: raw, unapproved material waiting for work
  • Outputs: approved final artifacts

Do not let an agent treat an Input as approved truth. Keep the state visible in the folder name and file.

Why three adapter files exist

There is no single magic filename every model reads identically.

  • Claude Code reads CLAUDE.md. Anthropic explicitly recommends a thin CLAUDE.md that imports @AGENTS.md when a repository already uses AGENTS.md.
  • Codex reads AGENTS.md and AGENTS.override.md from the project hierarchy, subject to its project-document budget.
  • Gemini CLI reads GEMINI.md by default and supports @file.md imports. Its context.fileName setting can also include AGENTS.md.

The starter uses:

CLAUDE.md → @AGENTS.md
GEMINI.md → @./AGENTS.md
AGENTS.md → PROJECT_MAP.md + shared operating rules

Shared context lives once. Model-specific behaviour stays thin.

Migrate a messy project

  1. Inventory, do not reorganise yet. List the current files, chats, links, and recurring tasks.
  2. Choose one source of truth per topic. Mark duplicates and stale copies.
  3. Write PROJECT_MAP.md. Point to the chosen sources.
  4. Move durable choices into Decisions.
  5. Turn one repeated task into a Process.
  6. Separate raw Inputs from approved Outputs.
  7. Add the three thin adapters.
  8. Run one real task with each model.
  9. Fix missing context at the source, not inside a new giant prompt.
  10. Archive duplicates only after the new map works.

The portability test

Give a blank-session model one task and the folder. It should be able to answer:

  • What am I trying to produce?
  • Which files are authoritative?
  • What decisions are already closed?
  • What needs human approval?
  • What proves the task is done?

If it cannot, improve the map or process. Do not duplicate the whole context into another adapter.

Important boundary

This folder gives supported agent tools discoverable Markdown. A generic chat model still needs the files uploaded or connected. Instructions are context, not hard access control. Use permissions and tool gates for actions that must be blocked.
