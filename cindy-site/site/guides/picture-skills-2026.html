Top skills to learn in 2026

Hey, it's Cindy 🌱 The skills to learn in 2026, plus a prompt that turns one project idea into a first project to practise the skill you need most.

The useful question is which skill will help you build something you currently can’t. This is a shortlist of six skills that work well together: directing AI, questioning data, using APIs, designing workflows, communicating visually and testing AI output.

You do not need to learn all six before making anything. Pick the skill that removes your current bottleneck, then use a small project to practise it. This is an editorial learning route, not a salary ranking or a promise of a job.

To make the route concrete, we’ll use one fictional project: a weekly enquiry report for a small business. It should show how many enquiries arrived, where they came from and which records need attention. The finished version is a clear one-page report with a traceable source for every number.

part 01

1. AI direction: turn a vague ask into a usable brief

Start with AI Fluency: Framework & Foundations. It introduces ways to collaborate with AI and evaluate the work. Course access and your chosen AI product are separate; you can practise the ideas in a chat tool you already have.

The skill is deciding what the AI needs to know to do a job well. For our report, “analyse my leads” is missing the date range, definitions, source and intended decision. A better brief explains that the reader needs to compare enquiry sources and spot incomplete records, using only the supplied data.

Ask for a result with a defined shape: three findings, a small table and any data-quality problems. Include an example of a useful finding. “There are two records without a source” is grounded. “Your strategy is failing” needs far more evidence.

Practise by giving the same data to a vague prompt and a precise prompt. Judge whether the second result is easier to verify and use, rather than whether it sounds more confident.

part 02

2. Data literacy: check where the number came from

Start with Harvard’s CS50 Introduction to Databases with SQL. Begin with querying, then study relationships between tables. The public course material is available to work through; certification options and their terms are separate from learning the material.

SQL is useful because it makes your question explicit. Here is a complete toy example you can run in a SQLite practice database:

CREATE TABLE enquiries (
  id INTEGER PRIMARY KEY,
  source TEXT,
  complete INTEGER
);
INSERT INTO enquiries VALUES
  (1, 'Instagram', 1),
  (2, 'Instagram', 0),
  (3, 'Search', 1),
  (4, 'Referral', 1);

SELECT source, COUNT(*) AS enquiries,
       SUM(complete) AS complete_enquiries
FROM enquiries
GROUP BY source
ORDER BY enquiries DESC, source;

This invented dataset produces two Instagram enquiries, one complete; the other sources each have one complete enquiry. Those are counts, not revenue or lead quality. Keeping that distinction clear is part of data literacy.

After running it, change one row and predict the result before rerunning. If your prediction differs, inspect the query until you understand why. You should be able to explain every number in your report.

part 03

3. API literacy: see the exchange between apps

Start with the Postman quick start. An API is a way for software to exchange information. A request specifies what you want to do, and the response tells you what happened or returns data.

Follow the public example, then identify the URL, method and response body. For the enquiry project, a future API connection might read records from a form system. Before building that, find the service’s official documentation and confirm which endpoint returns the records you need.

Learn the difference between a successful response and the correct data. A request can succeed while returning an empty list or only one page of results. Check pagination, date filters and missing fields before treating an API response as a complete report.

You can learn with public examples before connecting a paid service. Account permissions, rate limits and billing depend on the API you eventually use.

part 04

4. Workflow design: make the handoff reliable

Start with n8n’s first-workflow guide. Follow the example to understand the trigger, data passing and conditional branches. You’ll need an n8n environment; Cloud and self-hosted options have different costs and responsibilities.

Map your enquiry report as a sequence: fetch records, check required fields, count the valid records, produce a draft and send it for review. Give invalid records their own path so they are visible rather than silently disappearing.

For the first practice version, use a manual trigger and sample data. Then deliberately run the same input twice. Does it create duplicate records or duplicate reports? Decide how the workflow should recognise the same reporting period before scheduling it.

A useful workflow includes a failure path. If the source is unavailable, the output should say the report could not be completed. It should not publish an empty report that looks like the business received zero enquiries.

part 05

5. Visual communication: make the decision easy to see

Start with Figma’s design-basics library. Use its articles to study hierarchy, layout and typography, then practise in whichever design tool you already use. The learning library does not require you to purchase every feature of the Figma product.

Take the report and give it one clear reading order: reporting period, total enquiries, source breakdown and exceptions requiring attention. Use spacing and type size to make that order visible.

Label the toy data as an example. If you draw a bar chart, keep the scale honest and show the counts. Avoid decorating the page with charts that do not help answer the question.

Your check is simple: show the page to someone for a few seconds and ask what it says. If they notice decoration but miss the reporting period or the incomplete records, adjust the hierarchy before adding more content.

part 06

6. AI evaluation: test the output against expectations

Start with Anthropic’s prompt-evaluation lessons. You can read the notebooks for the concepts; running API exercises requires the relevant setup and may incur usage charges. Check older code examples against current SDK and model documentation.

Build five test cases for your report: clean data, missing source, duplicate record, empty period and a record with a misleading note. Decide the correct behaviour before asking AI to produce the summary.

For example, the empty period should report zero enquiries only if the data source was successfully checked. A connection failure should produce an error, not the same conclusion. That single distinction catches a much more useful failure than asking another AI whether the writing “looks good.”

Keep the tests when you change the prompt so you can see whether a revision improved one case while breaking another.

part 07

Ask Claude to build your first practice project

copy this prompt
Help me learn through a small weekly enquiry-report project.

My current level: [describe what you can already do].
Time available this week: [time].
Tools I have: [list].
Data: [paste fictional or appropriately de-identified sample rows].

Choose the one skill among AI direction, SQL, APIs, workflow design, visual communication and evaluation that would remove my biggest immediate bottleneck. Explain your choice briefly.

Then produce a usable first artifact: the precise report prompt, runnable SQL for a declared database, a public API practice request, a workflow specification, a one-page report layout, or five evaluation cases. Choose the artifact that matches the skill. Do the work using my sample data instead of giving me a blank worksheet.

Explain how I run or use it, what result I should expect, and two ways to test it. Separate invented example data from actual results. Link the relevant official learning resource. Do not invent business performance or recommend buying a course before I have tried the exercise.

Start with the artifact you can finish this week. You’re making progress when you can run it, explain it and identify where it fails. Then the next skill has a clear purpose because it improves something you have already built.
