the reasoning

Why a project beats a badge

Hiring managers in 2026 are scanning for evidence you can actually use AI, not another line in a "certifications" list. A working tool you built shows judgement, initiative, and that you can ship, which a completion screenshot never proves.

This is the honest version of the point: certificates are not useless, they just don't differentiate you anymore because everyone can collect them. The differentiator is a concrete artifact plus a story about the problem it solved.

The best move is both: do the free fundamentals course for the vocabulary, and pair it with one real build for the proof.

the fundamentals

The free certificate worth pairing with a build

The ITU AI courses the viral videos push are real. ITU is the United Nations agency for digital technologies, and its ITU Academy runs genuinely free, online, instructor-led AI courses (for example "AI in practice" and "Artificial intelligence for the public sector"). They're $0, and you get an official ITU certificate if you score 70% or higher.

One heads-up: specific cohorts open and close on set dates and some cap places (around 30 people), so don't bank on a specific one being open today. Check the live catalogue for what's currently accepting registrations: academy.itu.int/training-courses/full-catalogue.

Bottom line: the certificate is a nice fundamentals layer. The thing that actually lands you the role is what you build next.

The exact prompt to turn a work task into a portfolio project

Open Claude, and paste this. Swap the bracketed bits for your real task. The point is to describe the messy manual thing you already do, not to sound technical.

✍️ task to portfolio project 
I want to build one small, real project I can show on my LinkedIn and talk through in an interview, to prove I can actually use AI at work. I am not a developer. Here is a task I currently do manually: [describe the boring task in plain sentences, e.g. "every Monday I copy numbers from 5 spreadsheets into one summary and email it to my manager"]. Please: 1) suggest the simplest useful tool that would automate this (a script, a dashboard, a mini agent, whatever fits), 2) build it, 3) give me step-by-step instructions to run it assuming I have never used a terminal, and 4) tell me, in one paragraph, how I'd describe this project in an interview so it sounds like real impact.
Why this works: it forces Claude to pick a scope small enough to finish, build the thing, AND hand you the interview story, so you leave with proof and a script to talk about it.
the proof

Capture the before-and-after

This is the part most people skip, and it's the whole point. Your portfolio proof is the contrast, not just the finished tool.

  1. 🎥 Record the "before." A quick screen recording or screenshot of the manual way (the messy spreadsheet, the copy-paste, the 30 minutes it takes).
  2. ⚡ Record the "after." The tool Claude built with you running in a few seconds.
  3. 🗒️ Write two sentences: what the task was, and what the tool changed (time saved, errors removed). That's your LinkedIn post and your interview answer.
go further

3 bonus prompts to run next

Turn it into a case study:

1 · the case study post 
Write a short LinkedIn post about the tool we just built. Lead with the problem, show the before-and-after, and keep it humble and specific. No hype, first person, about 120 words.

Prep the interview:

2 · the interview drill 
Act as a hiring manager for a role I want. Ask me 5 tough questions about the project we just built, then coach my answers so I sound like I understand what it does, not like AI did it for me.

Level it up:

3 · level it up 
Suggest 3 small upgrades to this tool that would make it more impressive to show, ranked by effort. Then build the easiest one and tell me what it now does.
pick your level

How to get the most out of it

If you're a beginner don't aim for something clever. The best first project is the most boring repetitive task you have, because the before-and-after is obvious and easy to explain. Let Claude pick the scope for you with the prompt above.
If you're further along chain it. Build the tool, then ask Claude to add it to a tiny personal site or a public GitHub repo so the proof has a permanent link you can drop straight into applications.
the honest bit

An honest heads-up

Don't oversell a tiny script as an enterprise system. The credibility comes from being specific and real: "I automated my weekly reporting and cut it from 30 minutes to under a minute." Interviewers respect a genuine small win far more than a vague big claim, and they can tell the difference fast.
