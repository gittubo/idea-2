the setup

Step 1: unlock your profile page

GitHub has a quiet feature: if a public repository's name matches your username exactly and it has a README.md with content, that README displays at the top of your profile like a front page.

  1. 🆕 On github.com, click the + (top right), then New repository
  2. ✍️ Under Repository name, type your username exactly (if your username is octocat, the repo must be octocat)
  3. 🌍 Select Public (required for it to show)
  4. ✅ Toggle Add README on, then click Create repository

Source (GitHub's official docs): Managing your profile README

Step 2: the Claude prompt

Open Claude (claude.ai or Claude Code, either works), paste your resume or a rough list of what you've built, then paste this:

🧠 the README builder 
Design my GitHub profile README. Here is my background: [paste resume or dot points].

Ask me up to 5 questions if anything important is missing, then output ONE complete README.md file with:

1. A waving header banner from capsule-render with my name:
   https://capsule-render.vercel.app/api?type=waving&text=MY+NAME
2. A typing animation from readme-typing-svg cycling 3 short lines about what I build:
   https://readme-typing-svg.demolab.com?lines=Line+one;Line+two;Line+three
3. A short About section, first person, 3 to 4 lines, no buzzwords, only facts I gave you.
4. A badge row of the tools I actually use, built with https://img.shields.io/badge/ static badges.
5. Live stats cards: https://github-stats-extended.vercel.app/api?username=MYUSERNAME plus its top languages card.
6. A "Featured builds" section: a table of my 3 best repos with a one-line outcome each (link them).
7. Contact buttons (LinkedIn, email, website) as clickable shields badges.
8. HTML comments marking each section so I can edit pieces later.

Rules: replace MYUSERNAME with my real GitHub username everywhere, do not invent numbers,
certifications, employers, or projects, keep everything in sentence case, and center the header.

Claude streams out the whole file. Read the About section before you ship it, it should sound like you.

ship it

Step 3: paste and commit (no terminal)

  1. 📂 Open your new username repo and click Edit README
  2. 📋 Delete the placeholder, paste Claude's markdown
  3. 👀 Flip to the Preview tab to see it render live
  4. 💾 Click Commit changes, then visit your profile. It's live
under the hood

Step 4: the free tools doing the magic

Every animated piece is a free open source project rendering a live image inside your README:

  • 🌊 Capsule render, the waving header banner: github.com/kyechan99/capsule-render
  • ⌨️ Readme typing SVG, the animated typing intro (there's a point-and-click builder at readme-typing-svg.demolab.com/demo): github.com/DenverCoder1/readme-typing-svg
  • 🏷️ Shields.io, the little badges for tools and contact buttons: shields.io
  • 📊 GitHub Stats Extended, the live stats and top-languages cards: github.com/stats-organization/github-stats-extended
  • 📈 Activity graph, the line chart of your last 31 days: github.com/ashutosh00710/github-readme-activity-graph
Good to know: the classic github-readme-stats project you'll see in older tutorials is officially no longer maintained, its own README now points to GitHub Stats Extended as the actively maintained successor (source: github.com/anuraghazra/github-readme-stats). Use the Extended one, it's the same card style with more features.

Because they're live images, the cards update themselves every time you push something new. A brand new account will show small numbers, and that's fine, the page is proof you build, not a vanity contest.

optional flex

Step 5 (optional flex): the snake that eats your contribution graph

The snake is Platane/snk, a free GitHub Action that regenerates an animated SVG of a snake eating your green squares: github.com/Platane/snk

It needs one workflow file in your profile repo. Let Claude do it, paste this in the same chat:

🐍 the snake setup 
Now add the contribution snake to my profile repo using Platane/snk (the v3 GitHub Action).
Give me the exact .github/workflows/snake.yml file, the README embed line, and click-by-click
browser instructions to add the file, grant the action permission to push, and run it once manually.

This is the one step that touches GitHub Actions, and it's still all in the browser.

the receipts

Step 6: pin your proof

Your README is the poster, your pinned repos are the receipts. GitHub lets you pin up to six repositories and gists combined (source: Pinning items to your profile).

What counts as a build if you're a marketer going technical:

  • 🗂️ A prompt library or CLAUDE.md setup you actually use
  • ⚙️ An automation script Claude wrote for you (content repurposer, report generator, scraper)
  • 📉 A dashboard or tracker you built with Claude
  • 📝 Each pinned repo gets a tiny README of its own: what it does, what it replaced, one screenshot
what to watch

Keep it honest

✅ Only list certifications, numbers, and projects that are real, the prompt already forbids Claude from inventing any
🔓 The profile repo must be public, so never paste anything private into it
🐢 The free hosted card services can be slow under heavy traffic (both capsule-render and the stats projects say so in their docs). The stats cards also cache for a few hours to stay inside GitHub's API and Vercel rate limits, so new activity can take a few hours to show up. That's normal, not broken
